# 本地研究工作台与重构说明

## 架构与功能边界

保留原 CLI、自然语言意图分析、PubMed 检索、期刊筛选、大纲和文章生成；新增本地浏览器入口，不替换原业务逻辑。按职责划分：

| 层 | 文件 | 责任 |
|---|---|---|
| 浏览器展示 | workbench/templates、static | 表单、历史、文献详情、结果与日志 |
| HTTP | workbench/app.py | 本地请求校验、分页、下载与 API |
| 任务管理 | workbench/jobs.py | 独占运行、进程生命周期、历史成果快照 |
| 工作流适配 | workbench/worker.py | 复用核心流程、JSONL 事件、原交互输入 |
| 持久化 | workbench/store.py | SQLite 任务、文献、事件、成果索引、偏好 |
| 共用服务 | workflow_runtime.py、workflow_exports.py、journal_data.py | 状态、缓存、导出、完整期刊表加载 |

## 使用

1. 按 README 安装依赖、配置 `.env` 和期刊数据；使用 `python src/web.py` 启动。
2. 填写研究问题、检索篇数与原 AI 配置名称。界面不会自行添加额外筛选标准。
3. 默认在检索数量和生成前确认；原程序的具体选项显示于日志，回答框可留空使用原默认值。
4. 查看文献摘要、原始元数据及 PubMed 链接；查看大纲、Markdown 正文与成果下载。
5. 历史可按研究问题、文献标题或精确 PMID 搜索，支持状态过滤与分页；当前结果可按标题、期刊或 PMID 筛选。
6. “复用条件”只填回表单，点击开始后才新建任务；不会覆盖历史记录。

## 数据与安全

- 本地单用户设计，不包含多人账号、远程权限管理或云同步。SQLite 不加密，操作系统账户可读取本地历史；勿输入患者身份信息。
- 写接口要求同源令牌，服务限制回环地址和 Host；没有对公网部署的授权或配置。
- API 密钥沿用 `.env`，不保存在偏好表。工作进程事件做已知密钥和常见令牌脱敏；输入回答不留存为历史事件。
- 单个工作台只运行一个任务。CLI 保留原输出路径，因此不要与工作台并行执行检索；成果归属目前依赖输出文件变化快照。
- 日志有保留上限；文献和成果独立保存。任务失败/停止后只能查看实际产生的结果，不保证已取消请求未产生服务商费用。
- 服务重启后遗留任务标记为 interrupted，不伪装成自动断点恢复。
- 停止服务后备份整个 workspace_data 文件夹。该目录已被 Git 忽略。
